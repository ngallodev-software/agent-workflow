# Execution protocol

1. Treat sealed completion collections and final receipts as authoritative. Terminal text, mutable status projections, and prose-only claims are context.
2. Record source revision, clean/dirty state, pack validation, and the exact evidence files inspected.
3. Phase 0 may update evaluation contracts, collectors, scorers, ledgers, reports, and their focused tests only. Do not implement HARD or MSG runtime work in this pack.
4. Phase 1 may add strict `tests/future/` installed-product TDD journeys for planned work. Keep them honest expected failures tied to `CHATGPT-TDD-001` and the referenced future backlog items.
5. Preserve unavailable evidence as unavailable. Do not synthesize scores, tokens, costs, provider usage, acceptance, or ledger rows.
6. Run focused tests and release drift checks after each phase. Produce completion evidence with changed paths, commands, exit codes, unresolved issues, and no-drift declaration.
