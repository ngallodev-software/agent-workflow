# Benchmark real-host release-candidate gate

This is a review-and-evidence prompt pack for the remaining external gates on the 0.7.9 comparative benchmark subsystem. It does not reopen the benchmark design or authorize broad refactoring. It exists to exercise the integrated candidate on a real authenticated tmux/browser host, repair only defects exposed by that exercise, and produce a complete independently reviewable evidence bundle.

## Primary deliverables

1. `handoff-evidence/eval-results.json` conforming to `evals/evidence-schema.json`.
2. `handoff-evidence/evaluation-report.json` and `.md` generated by `evals/evaluate_handoff.py`.
3. Raw command, tmux, process, browser, benchmark, and review evidence referenced by every passing check.
4. A final independent gate report using `templates/FINAL_GATE_REPORT.md`.
5. Any narrowly scoped fixes, tests, and documentation updates required by real-host failures.

## Phases

| Phase | Purpose | Required outcome |
|---|---|---|
| 0 | Baseline, install, local deterministic gates, host readiness | Source and package are trustworthy before paid/provider work starts |
| 1 | Real Codex and Claude compact runs | Same-window panes, visible streams, usage, and under-three-minute model timing proven |
| 2 | Multi-phase, cancellation, live browser, and blinded review | Stable pane reuse, no orphan, preserved apps, scoring, and review proven |
| 3 | Teardown, evidence sealing, drift reconciliation, independent decision | Safe cleanup and a complete accepted evidence bundle |

## Non-targets

- changing historical `priority-picker-v1` semantics;
- weakening the v2 scoring contract or visual review;
- replacing subscription authentication with API keys without explicit operator choice;
- creating a generic plugin system for benchmark internals;
- claiming publication readiness from development-runtime evidence;
- inventing provider output, human reviews, timing, or browser observations;
- modifying acceptance criteria after observing a failure.

## Evaluation

The authoritative completion criteria are in:

- [`EVALUATION_PLAN.md`](EVALUATION_PLAN.md)
- [`evals/evaluation-manifest.json`](evals/evaluation-manifest.json)
- [`evals/evidence-schema.json`](evals/evidence-schema.json)
- [`evals/evaluate_handoff.py`](evals/evaluate_handoff.py)

The evaluator reports a 100-point diagnostic score, but every listed check is mandatory. Acceptance requires 100/100 and an independent final decision of `accept`.
