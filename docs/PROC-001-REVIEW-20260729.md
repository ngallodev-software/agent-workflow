## Findings

1. The ticket requires accepted, rejected, missing, and stale prerequisite
   dispositions. `resolve_prerequisites()` returns `missing` only inside the
   per-prerequisite detail and collapses the aggregate to `rejected`; it never
   produces a `stale` disposition. The `stale` type and error branch are
   unreachable from normal resolution, and no stale-receipt test exists.
2. Preflight calls `lifecycle_receipts(state_dir)` without binding the chain to
   the current sealed final-receipt digest. An accepted lifecycle receipt can
   therefore remain usable if its referenced final receipt is missing or no
   longer matches. Preflight must verify the sealed receipt and pass its digest
   into lifecycle-chain reconstruction, or apply an equivalent immutable
   binding.
3. The original delegated run
   `proc-001-interactive-r1-20260728` was interrupted while its pane was closed.
   Its run-level completion sidecar was initially the blocked placeholder and
   it still has no `final-receipt.json` or completion collection. The handoff
   was repaired and the agent assignment was completed, but this does not
   manufacture sealed evidence. Formal `review`/`accept` cannot be recorded
   for that run.

## Required next action

Launch an interactive corrective implementation for PROC-001 in a fresh
isolated worktree. Add explicit stale/invalid-sealed-receipt coverage, bind
preflight to the current final receipt, and require the agent to exit cleanly
after emitting the canonical handoff so the runner can collect and seal the
run. Then perform an independent review before acceptance.
